# Release v1.0.1 — Examples & API Reference
**Date:** 2026-05-20
**Compare:** `v1.0.0...v1.0.1`

## Summary

The "what every crate should ship from day one" patch. `v1.0.0` went
out with the audit-clean library code but two gaps in the user-facing
surface:

- No `examples/` directory. The inline doctest examples in `src/`
  showed usage but couldn't be run with `cargo run --example`.
- No flat-file API reference. `cargo doc` produced one, but a
  README-style `docs/API.md` is what most users look for first on
  GitHub.

Both closed in this patch. No code changes; no public API changes; the
`1.x` semver / wire-format / MSRV promises from `v1.0.0` carry forward
unchanged.

## Added

### Runnable examples (`examples/`)

Three end-to-end demonstrations, each a single self-contained file
gated on the `sha2` feature via `required-features`:

- **[`examples/in_memory.rs`](../../examples/in_memory.rs)** — the
  canonical first-look demo. Builds a chain with
  `Sha256Hasher + MemorySink + SystemClock`, appends three audit
  events (init / login / denied delete), prints them, then replays
  through `Verifier`.
- **[`examples/file_log.rs`](../../examples/file_log.rs)** —
  persistence demo. Writes a five-record chain to the system temp
  dir via `FileSink`, closes the writer, reopens the same path with
  `FileReader`, and verifies every record. Proves cross-session
  durability.
- **[`examples/tamper_detection.rs`](../../examples/tamper_detection.rs)** —
  the value-prop demo. Builds an in-memory chain, deliberately mutates
  one record's action, and shows `Verifier` rejecting it with the
  exact failing `RecordId`. Renders the headline guarantee
  ("tamper-evident") as a runnable proof.

Three `[[example]]` entries in `Cargo.toml`:

```toml
[[example]]
name = "in_memory"
required-features = ["sha2"]

[[example]]
name = "file_log"
required-features = ["sha2"]

[[example]]
name = "tamper_detection"
required-features = ["sha2"]
```

Run any of them with:

```bash
cargo run --example <name> --features sha2
```

### Public API reference (`docs/API.md`)

A flat-file reference for everything `pub` in the crate. Modelled
after the [metrics-lib API.md] structure: per-item signature, prose,
errors, and code examples; grouped logically; cross-referenced via
anchor links.

Sections:

- **Installation** + feature flag matrix.
- **Core types** — `Record`, `OwnedRecord`, `RecordId`, `Actor` /
  `Action` / `Target`, `Outcome`, `Timestamp`, `Digest`, `HASH_LEN`.
- **Pluggable traits** — `Hasher`, `Sink`, `Clock`, with worked
  examples for implementing each yourself.
- **Chain and Verifier** — full signature list, error contract,
  resume pattern.
- **Codec module** — every `pub fn` and `pub const`, with the wire
  layout diagrammed.
- **Reference implementations** — `MemorySink`, `FileSink<W>`,
  `FileReader<R>`, `Sha256Hasher`, `Blake3Hasher`, `SystemClock`.
  Includes the BLAKE3-vs-SHA-256 performance caveat.
- **Errors** — variant table for `Error` and `SinkError` with the
  trigger condition for each.
- **Patterns** — persistence + resume, replay-verify, custom database
  sink (using `codec::encode_record`), tamper-detection pointer.
- **Notes** — restates the `1.x` stability promises.

[metrics-lib API.md]: https://github.com/jamesgober/metrics-lib/blob/main/docs/API.md

### Repository restructure

- Moved `.dev/release/` → [`docs/releases/`](../releases/) via
  `git mv` (history preserved as renames).
- Moved `.dev/benchmarks/` → [`docs/benchmarks/`](../benchmarks/) via
  `git mv`.
- Untracked the remaining `.dev/` contents (`ROADMAP.md`, `PROMPT.md`,
  `DIRECTIVES.md`) — these are internal authoring docs that don't
  belong on the public crates.io repo. They remain in the local
  working tree, with `.dev/` now matched by `.gitignore`.
- Updated `.gitignore` pattern from `.dev/*` to `.dev/` (cleaner).
- Updated `docs/API.md` cross-references to the new paths.

The result: anyone browsing the public GitHub repo finds release
notes and benchmark baselines under `docs/` where they expect them;
private authoring artifacts stay private.
