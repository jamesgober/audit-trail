# Release v1.1.0 - Open, verify, resume
**Date:** 2026-10-28
**Compare:** `v1.0.1...v1.1.0`

## Summary

A service that keeps its audit chain in a file needs to open it at
start, prove that nothing in it was changed, and keep appending; it
needs the file private, the records on disk at known points, and a chain
that survives the wall clock stepping back. 1.0 had the pieces and left
the assembly to every caller. 1.1.0 adds them, without breaking
anything: the wire format, the MSRV, and every 1.0 signature are
unchanged.

## Added

- **`Chain::open_file`**: creates or opens a chain file, verifies every
  record, and returns a chain that appends after the last one, with an
  `OpenReport` (records verified, whether the file was created). A file
  that ends inside a record (a crash while writing) is `Error::Truncated`,
  reported apart from tampering (`HashMismatch`, `LinkMismatch`,
  `IdMismatch`), and the file is left unchanged.
- **`Chain::open_file_repairing_tail`**: the same, but an incomplete last
  record is cut off after its bytes are copied to `<path>.cut-<offset>`,
  so nothing is lost; records that fail verification are never cut.
- **Owner-only files**: `open_file` and the new
  `FileSink::open_or_create_private` create files with mode `0o600` on
  Unix.
- **Durability**: `FileSink::sync` (flush and `sync_data`), a provided
  `Sink::flush`, and `Chain::flush`.
- **`MonotonicClock<C>`**: timestamps that never go back, so a chain over
  the wall clock stays appendable through an NTP correction;
  `advance_past` and `Chain::clock` set it past a resumed chain's tail.

## Security

- `#![forbid(unsafe_code)]` at the crate root.
- A record's length is checked against the file's size before any
  buffer is allocated when opening a file.
