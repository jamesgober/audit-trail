# Release v0.7.0 — SystemClock & Reader Polish
**Date:** 2026-05-20
**Compare:** `v0.6.0...v0.7.0`

## Summary

The "stop rewriting the same boilerplate" release. Two changes, both
small, both worth shipping before the `0.9.0` audit phase locks the
public surface.

- **[`SystemClock`]** — every README example and every consumer of the
  crate has been writing the same `SystemTime::now().duration_since
  (UNIX_EPOCH)` adapter to satisfy the `Clock` trait. That adapter is
  now a first-class type behind the `std` feature. The Quick Start in
  the README dropped 12 lines of boilerplate to one.

- **`FileReader` scratch reuse** — the streaming reader used to
  allocate a fresh `Vec<u8>` for each record's frame buffer. It now
  reuses one internal buffer across the whole iteration, so a
  1 000-record replay drops from ~1 000 buffer allocations to one.
  The `OwnedRecord`'s three `String` allocations remain (they're
  required by the owning return type); this just eliminates the
  surrounding frame buffer churn.

Both changes are purely additive at the public surface — no existing
item changed signature, no existing test was rewritten.

## Added

### Clock (`std` feature)

- **`SystemClock`** — `Copy`, `Clone`, `Default`, `Debug` zero-sized
  type implementing `Clock` via `std::time::SystemTime`.
  - `SystemClock::new()` — `const fn`.
  - `now()` — returns nanoseconds since the Unix epoch. Saturates at
    `u64::MAX` for far-future timestamps. Returns `Timestamp::EPOCH`
    if the system clock is pre-epoch (unusual).
  - Documented caveat that `SystemTime` is **not** strictly monotonic;
    a deliberate operator clock-back triggers `Error::NonMonotonicClock`
    on the next `Chain::append`. Callers needing strict monotonicity
    should wrap `std::time::Instant` themselves.

## Changed

- **`FileReader`** internal structure gained a `scratch: Vec<u8>`
  field initialised with `Vec::with_capacity(256)` and reused across
  calls. `read_record` now does `scratch.clear()` + `scratch.resize`
  + `read_exact` into it, replacing the per-call `vec![0u8; ...]`.
  Public API and behaviour are unchanged.
- **README Quick Start (in-memory)** — replaced the inline 12-line
  `SystemClock` impl with `SystemClock::new()`.
- **README "Persisting to a file" example** — same swap.
- **README quick-start dependency snippet**: `"0.6"` → `"0.7"`.
- **Crate version**: `0.6.0` → `0.7.0`.

## Removed

- Nothing.

## Fixed

- Nothing user-visible. (The scratch-reuse refactor pre-emptively
  closes an allocation regression that would surface only under
  high-cardinality replay workloads.)

## Performance

`FileReader::next()` no longer performs a per-record `Vec<u8>`
allocation for the frame buffer. The internal `Vec` is resized in
place; for chains with bounded record sizes this means the buffer
allocates once and never grows. `OwnedRecord` still allocates three
`String`s per record (for actor / action / target) — that's required
by the owning return type and is unchanged.

`SystemClock::now()` is a single `SystemTime::now()` + `Duration`
arithmetic call. `Chain::append` performance is unchanged.

## Compatibility

- **Source compatible** with `0.6.x`. No existing public item changed
  signature, was renamed, or was removed.
- **Wire compatible** with `0.6.x`. Canonical hash encoding and
  on-disk codec format are unchanged.
- **Feature additivity** — `SystemClock` is gated on the existing
  `std` feature; no new feature flags introduced.
