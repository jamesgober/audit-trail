# Release v0.5.0 — Persistence
**Date:** 2026-05-20
**Compare:** `v0.4.0...v0.5.0`

## Summary

The persistence release. Through `v0.4.0` the crate could produce and
verify tamper-evident records, but it had no answer to "where do those
records live between the producer and the auditor." Every consumer had
to invent their own on-disk encoding — and any disagreement between the
producer's serialiser and the auditor's parser would break the chain
silently.

`v0.5.0` ships the answer:

- **[`codec`]** — a stable, versioned binary encoding for records.
  Hash-equivalent across producers and consumers; once a chain is on
  disk it can be replayed by any tool that speaks this format.
- **[`FileSink`]** — append-only file writer that uses `codec` and
  manages the file header automatically. Reopening the same path
  appends; brand-new paths get a header written for them.
- **[`FileReader`]** — `Iterator<Item = Result<OwnedRecord>>` over a
  chain file. Pairs directly with [`Verifier`] for end-to-end audit:
  open file, iterate, feed each record to the verifier, prove
  integrity.

The on-disk format embeds a one-byte version (`FORMAT_VERSION = 0x01`)
so future incompatible formats can coexist by bumping it. This format
is now a 1.0 stability commitment — `v1.0.0` will read every record
written by `v0.5.0`.

Three new `Error` variants surface codec and I/O failures with enough
detail for callers to distinguish recoverable issues (e.g. `Truncated`
at the tail, common on crash recovery) from permanent corruption
(`InvalidFormat`).

## Added

### Codec (`alloc` feature)

- **`codec`** module, publicly re-exported from the crate root.
- **`FORMAT_MAGIC`** = `b"AUDTRAIL"` (8 bytes).
- **`FORMAT_VERSION`** = `0x01`.
- **`FILE_HEADER_LEN`** = `16` (magic + version + 7 reserved bytes).
- **`write_file_header(out: &mut Vec<u8>)`** — append the 16-byte
  header to `out`.
- **`verify_file_header(bytes: &[u8]) -> Result<()>`** —
  `Err(Truncated)` if too short, `Err(InvalidFormat)` on bad magic or
  unknown version.
- **`encode_record(record: &Record<'_>, out: &mut Vec<u8>) -> Result<()>`**
  — append a length-prefixed record frame. Returns `Err(InvalidFormat)`
  if a string field's length would not fit in a `u32`.
- **`decode_record(bytes: &[u8]) -> Result<(OwnedRecord, usize)>`** —
  decode one record from the front of `bytes`, returning the consumed
  byte count for streaming use.

### Sinks (`std` feature)

- **`FileSink<W: Write>`** — append-only file-backed `Sink`.
  - **`FileSink::open_or_create(path)`** — wraps a `BufWriter<File>`;
    creates the file with header if absent, validates and seeks to end
    if present.
  - **`FileSink::new(writer)`** — for callers who manage the writer
    themselves.
  - **`FileSink::flush()`** — flush the inner writer.
  - **`FileSink::into_writer()`** — recover the inner writer.

### Readers (`std` feature)

- **`FileReader<R: Read>`** — streaming iterator over a chain file.
  - **`FileReader::open(path)`** — wraps a `BufReader<File>`.
  - **`FileReader::new(reader)`** — for arbitrary readers.
  - **`Iterator<Item = Result<OwnedRecord>>`** — header is validated
    lazily on first `next()`; cleanly returns `None` at EOF; terminates
    on the first error.

### Errors

- **`Error::Truncated`** — input ended mid-record.
- **`Error::InvalidFormat`** — magic / version / UTF-8 / length-prefix
  mismatch.
- **`Error::Io`** — underlying I/O failure (unit variant to keep
  `Error: Copy` and `no_std`-safe; full detail is available from the
  `io::Result`-returning constructors).

## Performance

The existing append / verify hot paths are unchanged.

New paths:

- **`encode_record`** does one `reserve` then a sequence of
  `extend_from_slice` / `push` calls — no intermediate allocations.
  Reuse the output `Vec` across records (e.g. `FileSink` does this via
  its `scratch` buffer) for amortised zero-cost encoding.
- **`decode_record`** does one `OwnedRecord` allocation plus three
  `String` allocations (actor / action / target). All `Copy`-fields
  are read in place from the input slice.
- **`FileSink::write`** reuses an internal `scratch: Vec<u8>` so the
  encode buffer is allocated once per sink, not per record.
- **`FileReader`** allocates a fresh frame buffer per record. A future
  release may switch to a streaming decoder that reuses a single
  scratch buffer; the public iterator API is forward-compatible.

## Compatibility

- **Source compatible** with `0.4.x`. No existing public item changed
  signature, was renamed, or was removed.
- **Wire compatible** with `0.4.x`. The hashing canonical encoding is
  unchanged. The codec format defined here is new in `0.5.0` and is
  the only producer of audit-trail file format `0x01`. There is no
  prior file format to be compatible with.
- **Feature gating** — `codec` requires `alloc`; `FileSink`/`FileReader`
  require `std`. Default features (`std`) gain `codec`, `FileSink`,
  `FileReader` transitively. `no_std` consumers see no public-surface
  changes.
