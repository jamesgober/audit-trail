# Release v0.6.0 — BLAKE3, Property Tests, Benchmarks
**Date:** 2026-05-20
**Compare:** `v0.5.0...v0.6.0`

## Summary

The quality release. `v0.5.0` made the crate end-to-end usable for real
audit logs; `v0.6.0` puts numbers on it and adds the second
production-grade hash option.

Three additions:

- **`Blake3Hasher`** behind a new `blake3` feature. Same `Hasher`
  contract as [`Sha256Hasher`], drops in wherever SHA-256 would go.
  BLAKE3 is materially faster than SHA-256 on modern hardware; the
  benchmark suite below quantifies it.
- **Property tests** — the codec round-trip and the multi-record
  pipeline now run 256 random cases per property via `proptest`, plus
  two adversarial properties that prove the decoder never panics on
  mutated or truncated input.
- **Criterion benchmarks** — two suites covering `Chain::append`
  throughput and `Verifier::verify` throughput across all three
  hashers (XOR / SHA-256 / BLAKE3).

The release also fixes a `cargo doc` warning that landed in `v0.5.0`
and was caught post-push: feature-gated rustdoc intra-doc links only
resolve when the feature is on, so `cargo doc` without `--all-features`
emitted `unresolved link to Sha256Hasher`. Fixed by switching
cross-feature prose to plain code formatting (no link).

## Added

### Hashers (`blake3` feature)

- **`Blake3Hasher`** — wraps `blake3::Hasher`. Implements the
  audit-trail `Hasher` trait via `reset` / `update` / `finalize`.
- `Blake3Hasher::new()`, `impl Default`, `impl Clone`, custom `Debug`
  that does not leak internal state.

### Property tests (dev-dep `proptest`)

- **`tests/codec_proptest.rs`** — 4 properties, ~256 cases each:
  - `encode_decode_roundtrip` — random valid records survive the
    codec round-trip with no leftover bytes.
  - `multi_record_roundtrip` — concatenated encoded records decode
    back to the original sequence in order.
  - `single_byte_mutation_never_panics` — flipping any post-prefix
    byte and decoding never panics; result is either `Ok` or `Err`.
  - `arbitrary_truncation_never_panics` — truncating the buffer at
    any offset and decoding never panics; result is always
    `Ok` or `Err(Truncated | InvalidFormat)`.

### Benchmarks (dev-dep `criterion`)

- **`benches/append.rs`** — `bench_append_xor`, `bench_append_sha2`
  (sha2 feature), `bench_append_blake3` (blake3 feature). Measures
  per-call `Chain::append` throughput.
- **`benches/verify.rs`** — `bench_verify_xor_1000`,
  `bench_verify_sha2_1000`, `bench_verify_blake3_1000`. Builds a
  1 000-record chain at start-up, then measures full-chain replay
  through `Verifier::verify`.
- Run via `cargo bench --features sha2,blake3`.

### Cargo

- New `blake3` feature, optional `blake3 = "1.5"` dependency
  (`default-features = false`).
- New dev-dependencies: `proptest = "1"`, `criterion = "0.5"`
  (`default-features = false`).
- Two `[[bench]]` entries with `harness = false`.

### Documentation

- README quick-start version bumped to `"0.6"`.
- README feature matrix gained a `blake3` row.
- README gained a "Benchmarks" subsection with the `cargo bench`
  invocation.

## Changed

- **Crate version** `0.5.0` → `0.6.0`.
- **`src/hashers/mod.rs`** is now `mod` declared under
  `cfg(any(feature = "sha2", feature = "blake3"))`, so the module is
  only compiled when at least one reference hasher is enabled.
- **`src/lib.rs`** — re-export of `Sha256Hasher` and `Blake3Hasher`
  each gated on their own feature with matching `#[cfg_attr(docsrs,
  doc(cfg(...)))]` annotations.

## Removed

- Nothing.

## Fixed

- **`cargo doc` unresolved-link warning.** Crate-level rustdoc
  formerly used `` [`Sha256Hasher`] `` which only resolved with
  `--all-features`. Switched to plain `` `Sha256Hasher` `` /
  `` `Blake3Hasher` `` in cross-feature prose so docs build cleanly
  in every feature mode.

## Compatibility

- **Source compatible** with `0.5.x`. No existing public item changed
  signature, was renamed, or was removed.
- **Wire compatible** with `0.5.x`. Canonical hash encoding and
  on-disk codec format are unchanged.
- **Feature additivity** — `blake3` is a brand-new opt-in. Default
  features (`std`) are unchanged.
