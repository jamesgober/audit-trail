# Release v0.4.0 — Reference Hasher & Owned Records
**Date:** 2026-05-20
**Compare:** `v0.3.0...v0.4.0`

## Summary

The "actually usable end-to-end" release. `v0.2.0` defined the surface and
`v0.3.0` added verification, but every consumer was still forced to write
three pieces of boilerplate before the crate did anything: a real hash
function, an owned record type, and a sink to put records into. As of
`0.4.0` all three are first-class:

- **[`Sha256Hasher`]** — production-grade reference hasher behind the new
  `sha2` feature. SHA-256 is the FIPS 180-4 primitive most compliance
  frameworks (HIPAA, SOC 2, PCI-DSS) accept by default.
- **[`OwnedRecord`]** — owned counterpart to the borrowed [`Record<'a>`]
  for storage, replay, and tampering tests. Symmetric `from_record` /
  `as_record` round-trip.
- **[`MemorySink`]** — in-memory reference `Sink` backed by
  `Vec<OwnedRecord>`. Useful for tests, prototypes, and short-lived
  buffering; not for long-running production workloads.

The crate now has a real Quick Start example in [README.md](../../README.md) — wire
`Chain::new(Sha256Hasher::new(), MemorySink::new(), …)` and you have a
verifiable audit log in under fifteen lines.

Feature surface gained one new flag (`alloc`) and one new opt-in
(`sha2`). The `std` default still implies `alloc` — existing consumers
opt into nothing they didn't already have.

## Added

- **`Sha256Hasher`** (feature `sha2`)
  - `Sha256Hasher::new()` — fresh hasher.
  - `impl Default`, `impl Clone`, custom `Debug` that does not leak
    internal state.
  - `impl Hasher` — `reset` rebuilds the inner `sha2::Sha256`; `update`
    forwards; `finalize` uses `finalize_reset` to avoid two-state copies.
- **`OwnedRecord`** (feature `alloc`)
  - Public-field struct mirroring every [`Record<'a>`] field with
    owned `String`s for actor / action / target.
  - `OwnedRecord::from_record(&Record) -> Self`
  - `OwnedRecord::as_record(&self) -> Record<'_>`
  - `From<&Record<'_>>` for ergonomic conversion in iterator chains.
- **`MemorySink`** (feature `alloc`)
  - `MemorySink::new()` (const), `MemorySink::with_capacity(usize)`.
  - `records()`, `into_records()`, `len()`, `is_empty()`, `clear()`.
  - `impl Sink` that pushes one `OwnedRecord` per write.
- **`tests/integration.rs`** — 4 end-to-end tests:
  - SHA-256-backed chain verifies clean,
  - Sha256 verifier detects field mutation at the correct record id,
  - Sha256 verifier detects a broken `prev_hash` link,
  - `OwnedRecord` → `Record<'_>` → `OwnedRecord` is a fixed point.
- **README Quick Start** rewritten with a working end-to-end example
  (Chain + Sha256Hasher + MemorySink + Verifier), plus a feature matrix
  table.
- Crate-level rustdoc now lists the optional features and what they add.

## Changed

- **Cargo features**
  - `default = ["std"]` (unchanged).
  - `std = ["alloc"]` (new transitive enable).
  - `alloc = []` (new).
  - `sha2 = ["dep:sha2"]` (new).
- **Dependencies**
  - Added optional `sha2 = { version = "0.10", default-features = false }`.
    Pulled in only when the `sha2` feature is enabled.
- **README Quick Start** — version bumped to `"0.4"` (with the
  `features = ["sha2"]` opt-in shown explicitly).
- **lib.rs** — `extern crate alloc` declared under `cfg(feature = "alloc")`
  so owned types compile in `no_std + alloc` builds.

## Performance

No changes on the existing append / verify paths. New items:

- `Sha256Hasher::finalize` uses `finalize_reset` — one digest copy, no
  spare hasher allocation. Subsequent `reset()` is the cheap path
  (replaces `self.0` with a fresh `Sha256`).
- `MemorySink::write` performs one `OwnedRecord::from_record` (3 small
  `String` allocations for actor / action / target) and one `Vec::push`.
  The append hot path is otherwise unaffected when callers use a
  zero-allocation custom sink.
- `OwnedRecord::as_record` is a borrow rebind — no allocations, no copies.

## Compatibility

- **Source compatible** with `0.3.x`. No public item changed signature,
  was renamed, or was removed.
- **Wire compatible** with `0.3.x`. Canonical record encoding is
  unchanged (`canonical` module bytes are byte-identical). A chain
  written by `0.3.x` with a custom SHA-256 hasher verifies byte-for-byte
  identically under `0.4.0`'s `Sha256Hasher`.
- **Feature gating** — adding `alloc` and `sha2` is purely additive. The
  default feature set (`std`) gains `alloc` transitively, which only
  *adds* `OwnedRecord` and `MemorySink` to the public surface.
