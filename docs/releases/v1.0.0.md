# Release v1.0.0 — Stable
**Date:** 2026-05-20
**Compare:** `v0.9.0...v1.0.0`

## Summary

`audit-trail` is stable. The pre-1.0 audit closed in `v0.9.0`; the
intervening commit is exactly the version bump and the milestone
declaration. The public surface is now under semver — additions are
allowed, breakage is reserved for `2.0`.

### What "stable" means here

- **API stability.** Every public item documented in the `1.0.0`
  rustdoc is part of the semver contract for the `1.x` line. New
  items may be added in `1.x`; nothing existing may be renamed,
  removed, or change signature.
- **Wire stability.** The on-disk codec format documented in the
  [`codec` module] is frozen for the current `FORMAT_VERSION = 0x01`.
  Any `1.x` reader will decode any `1.x` writer's output, byte for
  byte. A future incompatible format would bump the version byte;
  format `0x01` is permanently reserved for the encoding shipped here.
- **MSRV stability.** Rust 1.85 (the minimum required by
  `edition = "2024"`) is fixed for the `1.x` line. MSRV bumps are
  `2.0` material.

### What ships in 1.0

The public surface, in one glance:

| Category | Item | Notes |
|---|---|---|
| Core types | `Record<'a>`, `OwnedRecord`, `RecordId`, `Actor<'a>`, `Action<'a>`, `Target<'a>`, `Outcome`, `Timestamp`, `Digest` | The 5W + chain links. `Outcome` is `#[non_exhaustive]`. |
| Pluggable traits | `Hasher`, `Sink`, `Clock` | Intentionally open — pluggability is the design. |
| Chain | `Chain<H, S, C>` | Append-only, hash-linked log. `new`, `resume`, `append`, accessors, `into_parts`. |
| Verifier | `Verifier<H>` | Replays a chain and proves it untampered. `new`, `resume`, `with_strict_timestamps`, `verify`, accessors. |
| Errors | `Error`, `SinkError` | Both `#[non_exhaustive]`; `std::error::Error` impls under `std`. |
| Codec (`alloc`) | `codec::write_file_header`, `codec::verify_file_header`, `codec::encode_record`, `codec::decode_record`, format constants | Stable binary encoding. |
| Reference sinks (`alloc` / `std`) | `MemorySink`, `FileSink<W>` | Vec-backed and append-only file-backed. |
| Reference reader (`std`) | `FileReader<R>` | `Iterator<Item = Result<OwnedRecord>>`. |
| Reference hashers (features) | `Sha256Hasher` (`sha2`), `Blake3Hasher` (`blake3`) | Production-ready reference impls. |
| Reference clock (`std`) | `SystemClock` | Wall-clock backed by `std::time::SystemTime`. |
| Constants | `HASH_LEN`, `VERSION`, codec format constants | All hard-frozen. |

### What's NOT in 1.0 (deliberately)

- **Async API.** REPS forbids a hard async-runtime dependency. Users
  who need async can spawn the synchronous `append` on a blocking
  task.
- **Database / S3 / network sinks.** The `Sink` trait makes these
  trivial to implement out-of-tree; the crate doesn't bundle them.
- **`serde` integration.** Records have a stable binary codec; users
  who want JSON / other text formats can layer it on top of
  `OwnedRecord`.

These omissions are intentional. They keep the crate small, focused,
and free of dependency churn. Any of them can land in a `1.x` minor
release as an opt-in feature without breaking existing consumers.

## Compatibility

- **Source compatible** with `0.9.x`. No public item changed
  signature, was renamed, or was removed since the audit pass.
- **Wire compatible** with `0.9.x`. Same `FORMAT_VERSION = 0x01`,
  same record encoding, same canonical hash input.
- **MSRV** unchanged at Rust 1.85.
- **Feature flags** unchanged: `std` (default, implies `alloc`),
  `alloc`, `sha2`, `blake3`.

## Acknowledgements

`v1.0.0` is the result of seven releases of focused, fast-track
work — `0.1.0` scaffold through `0.9.0` audit. Every release shipped
with a release note, every line of public surface has a doc + a test,
and every CI failure that surfaced was diagnosed, captured as a
process memory, and fixed at root cause. The crate ships at `1.0.0`
the way the [REPS](../../REPS.md) standard demands: zero-allocation
hot path, no `unsafe`, no panics in shipping code, no required heavy
dependencies, `no_std` capable.
